# RWB Mesh Delivery Frontend

Для запуска нужен Node.js 20.19+ в 20-й ветке или Node.js 22.12+.

Из папки `frontend`:

```sh
npm ci
npm run dev
```

Стартовая страница `/` ведёт в кабинет ПВЗ (`/pvz`), кабинет продавца (`/seller`) и модель доставки (`/delivery-model`). Боковое меню и поиск работают без сервера API. Переключатель в шапке открывает рабочий раздел выбранной демонстрационной роли.

`npm run typecheck` генерирует типы из `../docs/openapi/frontend.yaml` и проверяет TypeScript. `npm run build` дополнительно собирает приложение в `dist`. При размещении сборки настройте возврат `index.html` для маршрутов приложения.

Клиент использует `/api/v1`. При локальной разработке оставьте `VITE_API_BASE_URL=/api/v1` и задайте `MESH_API_PROXY_TARGET` в `frontend/.env.local`. В качестве значения укажите адрес gateway без пути, например `http://127.0.0.1:8081`. Vite перенаправит запросы `/api/v1` и передаст `Location` для опроса статуса команд. Если к серверу нужно обращаться напрямую с другого origin, задайте полный `VITE_API_BASE_URL` с путём `/api/v1`. В таком режиме серверу нужно разрешить CORS и открыть заголовок `Location` для браузера. Для активного демонстрационного прогона настройте `VITE_API_DEMO_MODE=true`.

При размещении сборки с `VITE_API_BASE_URL=/api/v1` направьте `/api/v1` в gateway до обработки SPA-маршрутов. Настройка `MESH_API_PROXY_TARGET` относится к локальному серверу Vite.

Кабинет `/pvz` открывается напрямую или через переключатель деморолей. Список ПВЗ загружается из API. При недоступности сервера или отказе в доступе кабинет показывает сообщение и предлагает повторить запрос.

Проверка кабинета на работающем API: выберите ПВЗ, откройте «Приёмка и остатки», примите партию из каталога и проверьте изменение остатков и вместимости. В «Очереди заказов» выберите заказ с резервом в этом ПВЗ и подтвердите сборку. Для заказа со статусом «Готов к выдаче» в ПВЗ назначения подтвердите выдачу. Результат появляется после завершения команды сервером, при повторной отправке той же команды используется прежний ключ идемпотентности.

В кабинете `/seller` укажите ID продавца. Если в каталоге есть товары только одного продавца, его ID подставится. Проверьте регистрацию товара, остатки по месту хранения, стоимость хранения конкретной партии и финансовый отчёт за выбранный период. `POST /batches` по текущему контракту выполняет оператор ПВЗ или диспетчер. Для заявки продавца на размещение партии и выбора точки из каталога хабов понадобится расширение публичного API.

На странице `/delivery-model` выберите город получения, ПВЗ и товар. Сравните варианты из котировки, переключите схему, проверьте карточку узла и создайте заказ с резервом. Существующий заказ можно открыть из списка. Его статус опрашивается, а схема обновляется при появлении новой версии маршрута. Блок событий показывает обратный путь, инциденты и длительное хранение по данным API. При `VITE_API_DEMO_MODE=true` можно запустить подготовленный backend демонабор.

Ограничения модели определяются публичным OpenAPI. Отправление и хранилище выбирает сервер. Котировка не принимает подмену вместимости, тарифов, загрузки, срока хранения или доступности узлов. API не описывает рейтинг, габариты, нагрузку сотрудников, спрос, отдельный справочник хабов и прогноз финансового результата участников по обоим вариантам. В графе неизвестный узел показан по ID, а экономика ПВЗ и маркетплейса показана по фактическим проводкам за период. Котировка доступна для сравнения в текущем сеансе расчёта, поскольку публичного чтения котировки по ID нет.

Для проверки нештатных ситуаций откройте заказ в `/delivery-model` и разверните «Возвраты и логистические сбои». У выданного заказа можно оформить возврат по строкам, подтвердить приём, физические этапы и осмотр. Для активного отправления можно зафиксировать сбой и запустить серверный пересчёт маршрута. Дельты стоимости и срока берутся из новой версии маршрута. При `VITE_API_DEMO_MODE=true` переведите модельные часы из блока демонабора, затем проверьте начисления и решение по партии в разделе длительного хранения. Сообщения сервера доступны в журнале уведомлений. Все изменения остатков и финансов проводит API.

Финансовая аналитика находится отдельно от операционного кабинета, на `/analytics`. Выберите ПВЗ, продавца или маркетплейс и период. Журнал проводок показывает источник, тариф и номер исходной записи для сторно. Для сравнения Mesh и доставки через хаб укажите два заказа с одинаковой корзиной и ПВЗ выдачи. Способ доставки задаётся выбором заказа в соответствующем поле. Карточка заказа не содержит политики котировки. Для покупателя отображаются цена и сроки, для продавца расчёт по заказам, для ПВЗ и маркетплейса проведённые записи за период. Проводки показаны отдельно для каждого участника. Сравнение прогнозной прибыли по альтернативным маршрутам потребует полей в OpenAPI.

Кнопка «Сохранить в PDF» доступна после загрузки отчёта или сравнения. Выгрузка использует применённый период и загружает все страницы выбранных проводок. В сравнении в PDF включаются показатели покупателя, расчёты выбранного продавца и журнал выбранного участника по обоим заказам. В диалоге печати браузера выберите «Сохранить как PDF».

Подготовка данных, шаги и результаты пяти сценариев MVP описаны в [проверке интеграции](INTEGRATION.md).
